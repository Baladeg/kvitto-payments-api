# Правила работы с проектом

- Все денежные значения в API и PostgreSQL — целые копейки. Не используйте float
  в расчёте цен, скидок и графиков рассрочки.
- Соблюдайте контракт API из тестового задания Квитто и согласованные бонусы;
  сохраняйте существующие тестовые сценарии.
- Идемпотентность защищайте UNIQUE-ограничением PostgreSQL и атомарным INSERT
  ON CONFLICT, а не только предварительным SELECT или блокировкой в Python.
- Проверяйте переходы статусов и выполняйте изменения в одной транзакции под
  SELECT FOR UPDATE. Не меняйте список разрешённых переходов без запроса.
- Тесты запускайте только на kvitto_test. Никогда не очищайте основную БД.
- После изменений запускайте полный pytest, ruff check . и pip check. Сообщайте
  фактические результаты; не отключайте проверки и предупреждения ради успеха.
- Не храните реальные секреты в Git. WEBHOOK_SECRET обязателен при запуске;
  проверяйте HMAC по исходным байтам тела через hmac.compare_digest.
- Сохраняйте простую архитектуру. Не добавляйте эндпоинты и бонусы без запроса.
